# CORS wildcards (O-51). The one policy this API has reads an explicit origin list from
# `Cors:AllowedOrigins` and deliberately offers no escape hatch, but configuration is not the only way
# back to a wildcard -- a single line in AddCors reintroduces one, and with the anonymous stub identity
# the same-origin policy is the only access control there is. The analyzer is the mechanism the
# conventions treat as enforcement, so the escape hatches are named here.
#
# AllowAnyOrigin and SetIsOriginAllowed(...) are parameterless / single-overload methods, so the
# documentation ID is exact; CorsPolicyProbeTests plants a call against each of these entries and
# asserts the compiler rejects it, because a near-miss ID binds to nothing and reports nothing.
M:Microsoft.AspNetCore.Cors.Infrastructure.CorsPolicyBuilder.AllowAnyOrigin;Reflects any origin. Add the origin to `Cors:AllowedOrigins` instead (conventions §2, edge configuration).
M:Microsoft.AspNetCore.Cors.Infrastructure.CorsPolicyBuilder.SetIsOriginAllowed(System.Func{System.String,System.Boolean});A predicate is a wildcard nobody reads as one. Add the origin to `Cors:AllowedOrigins` instead.
